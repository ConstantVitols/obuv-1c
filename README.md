# ООО «Обувь» — МагазинОбуви

Учебное приложение на платформе «1С:Предприятие 8» для просмотра каталога обуви,
работы с товарами и заказами. Подготовлено для демонстрационного экзамена
09.02.07-2-2026.

> Подготовительный комплект: перед сдачей необходимо добавить актуальные
> `Source/`, `Database/03_Final.dt` и `Images/` из итоговой рабочей базы.

## Состав проекта

| Путь | Содержимое |
| --- | --- |
| `Source/` | Полная выгрузка конфигурации в XML и BSL, включая роли и комментарии |
| `Database/03_Final.dt` | Итоговая выгрузка информационной базы с данными |
| `Images/` | Актуальные фотографии товаров и заглушка `picture.png` |
| `Resources/import/` | Исходные Excel-файлы, фотографии и изображения из задания |
| `Docs/01_ER_Diagram_Obuv.pdf` | ER-диаграмма базы данных и пояснения |
| `Docs/02_Algorithm_Obuv.pdf` | Алгоритм разработки на одной странице |
| `Docs/03_Debug_Authorization_Obuv.docx` | Результаты отладки авторизации с фактическими снимками экрана |
| `Docs/Editable/` | Редактируемые исходники диаграмм в формате draw.io |

В `Source/` должен находиться `Configuration.xml` непосредственно вместе с
каталогами `Catalogs`, `CommonModules`, `DataProcessors`, `Documents`, `Roles`
и другими каталогами выгрузки. Исходные файлы размещаются развёрнутой
структурой, доступной для просмотра в GitHub.

## Среда разработки

- Разработка и проверки выполнялись в учебной платформе 1С 8.3.22.1709.
- Режим совместимости конфигурации — 8.3.21.
- Основной режим запуска — управляемое приложение, интерфейс «Такси».
- Используется файловая информационная база под Windows.

Приложение запускается средствами установленной платформы 1С. Для его
демонстрации предназначена итоговая база `.dt`; отдельный установщик или
самостоятельный EXE проекта не формируется.

## Восстановление и запуск

1. Скачать содержимое репозитория и распаковать его в отдельную папку.
2. В стартовом окне 1С создать новую пустую файловую информационную базу.
   Для проверки восстановления использовать отдельную базу, сохраняя рабочую.
3. Открыть новую базу в Конфигураторе и выполнить
   **Администрирование → Загрузить информационную базу**.
   Выбрать `Database/03_Final.dt`.
4. Скопировать папку `Images` из репозитория в каталог созданной базы,
   рядом с её файлом `1Cv8.1CD`. Должен получиться путь
   `<каталог базы>\Images\picture.png` и файлы фотографий в той же папке.
5. Запустить базу в режиме **1С:Предприятие**.
6. В выборе пользователей платформы использовать `ЗапускМагазина` для работы
   с приложением или `АдминистраторИБ` для технического обслуживания.
7. В форме входа магазина ввести логин и пароль нужной учебной учётной записи
   из `Resources/import/user_import.xlsx` либо выбрать гостевой доступ.

Фотографии хранятся вне информационной базы. Один файл `.dt` не заменяет
актуальную папку `Images`. Папка `Resources/import` содержит исходные материалы;
она не подменяет фотографии, добавленные или заменённые в редакторе товара.

## Вход и права доступа

Пользователи платформы 1С и пользователи магазина выполняют разные задачи.

| Пользователь платформы | Назначение |
| --- | --- |
| `АдминистраторИБ` | Конфигуратор, администрирование базы и технический просмотр данных |
| `ЗапускМагазина` | Запуск приложения без административных полномочий платформы |

В учебной версии платформы установка паролей пользователей информационной
базы недоступна. В учебном комплекте эти пользователи создаются без паролей.
Если пароли заданы позднее на полной платформе, сведения для входа передаются
проверяющему отдельно.

Роль внутри магазина определяется собственной авторизацией по справочнику
`Пользователи`. Логины и исходные пароли соответствуют выданной учебной таблице;
в справочнике хранятся соль и хеш пароля.

| Роль магазина | Доступные действия |
| --- | --- |
| Гость | Просмотр каталога товаров |
| Клиент | Вход в свою учётную запись и просмотр каталога |
| Менеджер | Просмотр каталога, поиск, фильтрация, сортировка и просмотр заказов |
| Администратор | Возможности менеджера, добавление, изменение и удаление товаров и заказов |

Разграничение действий внутри магазина выполняет серверный код приложения.
Платформенные роли в этой схеме отделяют техническое администрирование от
обычного запуска и не назначаются автоматически при смене пользователя магазина.

## Возможности приложения

- Вход по логину и паролю и гостевой просмотр.
- Отображение ФИО пользователя и роли.
- Каталог с фотографиями, описанием, поставщиком, производителем, остатком,
  исходной ценой, ценой со скидкой и размером скидки.
- Голубой фон при нулевом остатке; при наличии товара и скидке свыше 15% —
  зелёный фон. При одновременных условиях приоритет имеет нулевой остаток.
- Совместное применение поиска по текстовым полям, отбора по поставщику
  и сортировки по количеству на складе.
- Создание и изменение товаров, проверка обязательных полей и уникальности
  артикула, сохранение неизменяемого ID существующего товара.
- Выбор, замена и удаление фотографии; для новых изображений допускаются
  PNG/JPG/JPEG размером не более 300×200 пикселей.
- Запрет удаления товара, который присутствует в заказе.
- Просмотр заказов, их создание, изменение и удаление администратором.
- Выпадающие списки статусов, клиентов, пунктов выдачи и товаров в редакторе заказа.
- Обновление каталогов после сохранения и удаления данных.

## Импорт и просмотр исходных данных

Для технического показа запустить базу как `АдминистраторИБ` и войти
администратором магазина. В меню приложения открыть
**Настройки → Параметры**, включить **Режим технического специалиста**,
затем открыть **Функции для технического специалиста**.

| Данные | Путь |
| --- | --- |
| Обработка импорта | Обработки → Импорт начальных данных |
| Пользователи, товары и связанные справочники | Справочники → соответствующий справочник |
| Заказы и их состав | Документы → Заказ → открыть документ |

Обработка использует четыре файла из выбранного каталога:
`user_import.xlsx`, `Пункты выдачи_import.xlsx`, `Tovar.xlsx`, `Заказ_import.xlsx`.

Исходный набор содержит 10 пользователей, 36 пунктов выдачи, 30 товаров,
10 заказов и 20 строк состава заказов. В итоговой базе количество может
отличаться, если оставлены созданные при проверке записи.

Повторная загрузка сопоставляет существующие записи по ключам и не создаёт
их заново. Начальный импорт в пустую базу выполнялся на этапе первоначального
заполнения, до установки проверок редакторов. Для демонстрации первичного
импорта используется отдельно подготовленная база этого этапа; обычный запуск
готового приложения выполняется из итогового `.dt`.

В исходном файле заказов предусмотрена точечная поправка известной даты:
у заказа №7 значение 30.02.2025 заменяется на 28.02.2025. Остальные ошибочные
даты вызывают сообщение об ошибке. При успешном импорте выводятся количества
записей по типам и надпись «ИМПОРТ ЗАВЕРШЁН».

Исходные фотографии из задания могут иметь размер 500×500. Они были
загружены при первичном импорте. Ограничение 300×200 применяется к новым
фотографиям, выбираемым через редактор; неизменённые импортированные
изображения повторно по размерам не проверяются.

| Критерий | Материал |

| 1.1, 1.2, 1.4 | База с импортированными данными и метаданные в `Source/` |
| 1.3 | `Docs/01_ER_Diagram_Obuv.pdf` |

Функциональные проверки выполнялись пользователем в настольной 1С.
После получения итоговых файлов проверяются состав выгрузки, наличие
комментариев и ролей, соответствие путей к изображениям и полнота комплекта.
